# Lab 06: Harness Log Analysis Report

이 문서는 Lab 06에서 제공되는 `harness.log` 파일을 분석한 결과를 요약합니다. 반복적으로 발생하는 오류 유형을 식별하고, 각 오류의 특징적인 메시지를 정리하여 개선 사항을 도출하기 위한 자료로 활용합니다. 실제 로그를 분석한 후, 아래 내용에 맞추어 내용을 채워 넣으세요.

## 분석 방법

1. `log_analyzer.py` 스크립트를 이용해 `harness.log`를 카테고리별로 분류합니다.
2. 분류된 메시지를 살펴보며 동일한 오류 유형이 반복되는지 확인합니다.
3. 오류를 재현할 수 있는 테스트 케이스나 상황을 추정하고, 원인을 추론합니다.

## 상세 분석

### 1. Syntax 오류

간결하게: 여기에는 구문 오류나 들여쓰기 오류 등이 포함됩니다. 코드가 파이썬 인터프리터에 의해 해석될 수 없는 경우 발생합니다. 예를 들어 `SyntaxError: invalid syntax` 메시지는 문법이 잘못되었음을 의미합니다. 이러한 오류는 대부분 오타나 괄호, 콜론 누락 등 단순 실수에서 기인하므로 코드 리뷰와 정적 분석 도구를 통해 예방할 수 있습니다.

### 2. Logic 오류

이 영역에는 프로그램이 실행은 되지만 기대하는 결과를 산출하지 못하는 오류가 포함됩니다. 예를 들어 `Assertion failed: expected X to equal Y`와 같은 메시지가 나타나며, 이는 테스트에서 제공한 입력에 대한 출력이 올바르지 않음을 의미합니다. 이러한 문제를 해결하기 위해서는 요구사항을 다시 읽고, 테스트 코드를 통해 기대되는 동작을 정확히 파악해야 합니다.

### 3. Timeout 오류

`Execution timed out` 메시지는 프로그램이 일정 시간 내에 종료되지 않아 타임아웃 제한을 초과했을 때 발생합니다. 루프의 종료 조건이 잘못되었거나, 계산량이 많아 발생할 수 있습니다. 효율적인 알고리즘을 선택하고 불필요한 반복을 줄여야 합니다.

### 4. API 오류

네트워크 요청이나 외부 API 호출에서 발생하는 오류를 포함합니다. `ConnectionError`나 `TimeoutError` 등이 이에 해당합니다. 환경 변수나 API 키, 네트워크 연결 상태를 확인하고, 예외 처리 로직을 추가하여 안정성을 향상시킬 수 있습니다.

### 5. 기타 오류

위 네 가지 유형에 해당하지 않는 오류는 `other` 카테고리에 포함됩니다. 구체적인 메시지를 살펴보고 적절한 원인을 찾아 분류를 세분화할 수 있습니다.

## 결론

분석 결과 반복적으로 나타난 오류 유형을 중심으로 개선 방안을 도출할 수 있습니다. 가장 빈번하게 발생하는 오류를 우선적으로 해결하도록 조치하세요. 본 보고서는 예시일 뿐이며, 실제 `harness.log`를 분석한 후 데이터를 채워야 합니다.
