# Lab 06 Prompt v2 (Improved)

> **Tip**  
> v1 프롬프트의 기본 지시사항을 발전시켜, 반복적으로 발생하는 오류를 줄이고 코드를 체계적으로 개선하기 위한 추가 지침을 포함했습니다. A/B 테스트를 통해 v1 대비 성능을 비교할 수 있습니다.

## 목표

앞서 분석한 `harness.log`에서 나타난 패턴을 반영하여, 실패 원인을 빠르게 찾아 수정하고 모든 테스트를 통과시키는 것이 목표입니다.

## 지시 사항

1. **테스트 실행 전 준비**  
   - 저장소를 깨끗한 상태로 초기화하고, 의존성을 설치합니다.  
   - `pytest tests/ -q --tb=short` 명령어를 실행하여 전체 테스트 목록과 실패 사례를 파악합니다.
2. **실패 테스트 분석**  
   - 실패한 테스트와 직접 관련된 파일만 열어 필요한 부분만 수정하십시오.  
   - 오류 메시지를 `syntax`, `logic`, `timeout`, `api`, `other` 카테고리로 분류하여 가장 큰 영향을 미치는 오류부터 해결하세요.
3. **수정 및 최소 변경 원칙**  
   - 코드를 수정할 때는 최소한의 변경으로 목표를 달성합니다.  
   - 동일한 오류가 반복될 경우, 먼저 **원인 분석**과 **해결 계획**을 `fix_plan.md`에 정리한 뒤 수정하세요.
4. **반복 오류 대응**  
   - 수정 후에도 같은 오류가 발생하면, 루프에 갇히지 않도록 새 접근법을 시도하거나 팀원과 상의합니다.  
   - 문제를 해결하지 못하는 경우, 추가 가이드라인을 참고하거나 문제를 더 작게 나누어 접근합니다.
5. **테스트 통과 후 마무리**  
   - 모든 테스트가 성공할 때까지 반복합니다.  
   - 성공하면 `DONE.md` 파일을 생성하여 `all tests passed`라는 내용을 기록합니다.  
   - 수정 내역과 개선 사항을 `README.md`에 명확하게 정리합니다.

## 개선 사항 요약

* 오류를 체계적으로 분석하고 우선순위를 지정함으로써 효율적인 문제 해결을 유도합니다.
* 반복 오류를 방지하기 위해 수정 계획(`fix_plan.md`)을 문서화합니다.
* 테스트 실행 전 후에 정확한 상태를 확인하고, 루프를 최소화합니다.

## 참고 사항

* 커밋 메시지와 마크다운 스타일 가이드라인은 v1과 동일하게 준수합니다.
* Python, bash 등 실행 가능한 코드 블록에는 언어를 명시하십시오.
* 분석 결과는 `error_report.md`와 `ab_results.json`에 기록합니다.
