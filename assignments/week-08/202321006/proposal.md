# 실시간 지식 독점 방지 및 협업 넛지 에이전트

**한 줄 요약**: GitHub PR 발생 시 실시간으로 버스 팩터를 계산하여 지식 독점을 감지하고, AI 인터뷰를 통해 설계 맥락을 추출하여 적합한 팀원에게 지식을 분산시키는 능동형 협업 에이전트

## 1. 문제 정의

### 1.1 현재 상황
소프트웨어 팀에서 지식 독점 문제는 퇴사 이후에야 발견된다. 이는 팀의 영속성을 해치는 심각한 위험이다.
- 특정 모듈을 오직 한 명만 이해하고 있어, 그 사람이 없으면 수정·디버깅이 불가능
- "문서화"는 귀찮고 고통스러운 작업이라 아무도 하지 않음
- 결국 퇴사 통보 후에야 패닉 상황 반복

**핵심 문제**: 지식 독점은 실시간으로 쌓이는데, 이를 감지하고 개입하는 시스템이 없음.

### 1.2 왜 에이전틱 접근인가
- **능동적 개입**: 사후 통계가 아닌, PR 발생 즉시 에이전트가 개입하여 지식 증발 차단.
- **Ralph Loop**: 모호한 답변을 정교하게 다듬어 고품질 설계 맥락(Rationale) 추출.
- **Human-in-Command**: 에이전트는 제안하고, 최종 결정은 사람이 하는 조화로운 협업.

## 2. 제안 시스템 설계

### 2.1 에이전트 구성 (Multi-Agent Pipeline)
| 에이전트 | 역할 | 분석 및 대응 메커니즘 (Key Feature) | 모델 |
|----------|------|------------------------------------|------|
| StreamWatcher | PR 실시간 감지 | **Semantic Diff 분석**: 단순 포맷팅 제외, 유의미한 로직 변경점만 추출 | Haiku 4.5 |
| RiskEvaluator | 다차원 위험 분석 | **Bus Factor Entropy + Impact Analysis**: 사회/기술적 위험도 산출 | Sonnet 4.6 |
| Interviewer | 설계 맥락 추출 | **Zero-Draft + Consistency Check**: 답변-코드 일치성 검증 (Ralph Loop) | Sonnet 4.6 |
| NudgeManager | 지식 전파 및 추천 | **Knowledge Proximity**: 최적의 지식 전수 대상자(리뷰어) 추천 | Sonnet 4.6 |
| GateKeeper | 최종 거버넌스 | **Trust-based Gating**: 신뢰 점수에 따른 유연한 병합 통제 | Sonnet 4.6 |

### 2.2 분석 프레임워크: Multi-Dimensional Risk Engine
본 시스템의 설계가 탄탄한 이유는 세 가지 차원의 분석을 병렬로 수행하기 때문입니다.

1. **사회적 위험 (Social Risk)**: Bus Factor Entropy 계산을 통해 특정 인물에 집중된 지식 편중도를 수치화.
2. **기술적 위험 (Technical Risk)**: 수정된 모듈의 의존성(Dependency)과 수정 빈도(Hotspot)를 분석하여 장애 파급력 계산.
3. **맥락 일관성 (Consistency Analysis)**: 개발자의 답변과 실제 코드 변경점이 일치하는지 임베딩 분석을 통해 검증 (Ralph Loop 트리거).

## 3. 사용자 경험(DX): "Smart & Soft Nudging" 전략
탄탄한 분석이 개발자를 괴롭히는 '취조'가 되지 않도록 다음과 같은 실리적 전략을 적용합니다.

1. **Zero-Draft (대신 써주기)**: 에이전트가 코드를 먼저 분석해 "이런 의도인가요?"라고 초안을 제시. 개발자는 확인(Confirm)만 하면 끝.
2. **Adaptive Confidence (신뢰 기반 생략)**: 개발자가 평소 지식 공유를 잘해 '신뢰 점수'가 높다면, 사소한 불일치는 에이전트가 스스로 판단하고 재질문을 생략.
3. **Passive Capture (수동적 포착)**: 개발자가 바빠 답변을 못 하면 에이전트가 분석한 내용을 바탕으로 요약본을 자동 게시하여 워크플로우 방해 최소화.
4. **Positive Feedback**: "준서 님 덕분에 팀의 기술 부채가 줄었습니다!"와 같은 긍정적 피드백으로 동기 부여.

## 4. 파이프라인 아키텍처 및 시나리오

```
[PR 발생] -> StreamWatcher (감지) -> RiskEvaluator (분석: 위험도 92점)
    │
    ▼
[Interviewer 개입] 
    - AI: "코드 분석 결과, 캐시 로직 추가로 보입니다. 맞나요?" (Zero-Draft)
    - 개발자: [Confirm] 클릭
    - AI: (속으로 일관성 검증) "답변과 코드 일치 확인."
    │
    ▼
[Nudge & Gate]
    - NudgeManager: "가민 님, 이 캐시 로직은 준서 님 전담이니 이번에 꼭 보세요!"
    - GateKeeper: 지식 공유 점수 85점 -> Merge 승인
```

## 6. 성공 기준 및 기대 효과
- **Bus Factor 개선**: 지식 독점 모듈 40% 감소.
- **문서화 피로도 감소**: 수동 문서 작업 시간 80% 절감.
- **리뷰 퀄리티 향상**: 설계 의도를 미리 알고 리뷰에 참여함으로써 실질적인 피드백 증가.
