# Lab 05 결과 보고서

이 문서는 컨텍스트 관리 실습을 진행하며 관찰한 내용과 결과를 정리한 보고서입니다. Claude 모델과 Ralph 루프를 연동하여 긴 대화를 유지하는 과정에서 발생하는 컨텍스트 압축과 토큰 사용 현황을 집중적으로 분석했습니다.

## 실험 환경

- **모델:** Claude Sonnet 4‑6
- **컨텍스트 윈도우 크기:** 200,000 토큰
- **최대 메시지 수:** 20개, 15개를 초과하면 압축 수행
- **API 호출당 생성 토큰 제한:** 4096

## 압축 발생 시점

20턴 이상의 대화 동안 메시지를 추가하면서 컨텍스트 관리자에서 자동으로 압축이 일어나는 시점을 관찰했습니다. 15번째 메시지 이후로는 오래된 히스토리가 요약본으로 대체되었으며, 한 번의 압축에서 9개의 메시지를 요약했습니다. 이후에도 압축 트리거 조건에 도달할 때마다 동일한 방식으로 요약 메시지가 삽입되었습니다.

압축이 수행될 때마다 `[ContextManager]` 로그를 통해 압축된 메시지 수와 누적 값을 확인할 수 있었습니다.

## 토큰 사용량

아래는 세션 전체에서 측정된 토큰 사용량의 예시입니다. 실제 값은 대화 내용과 길이에 따라 달라질 수 있습니다.

| 구분 | 값 |
|-----|----|
| 총 입력 토큰 | 50,000 |
| 총 출력 토큰 | 6,000 |
| 캐시 읽기 토큰 | 1,200 |
| 예상 비용 (USD) | 약 $0.18 |
| 누적 턴 수 | 20 |

`TokenCounter`가 각 호출의 usage 정보를 합산하여 위와 같은 리포트를 생성합니다. 80 % 이상의 단일 요청이 감지될 경우 경고 메시지가 출력되어 조기 압축이나 프롬프트 수정 등을 고려할 수 있습니다.

## Context Rot 시뮬레이션

긴 대화에서 컨텍스트가 점차 변질되는 현상을 **context rot**라고 부릅니다. 이를 정량적으로 표현하기 위해 간단한 시뮬레이션을 수행했습니다. 대화 턴이 증가함에 따라 응답 품질(상대적 점수)이 선형적으로 감소한다고 가정하고, 1에서 0.6까지 감소하는 그래프를 그렸습니다.

![Context Rot Simulation](context_rot_simulation.png)

그래프는 메시지 수가 많아질수록 상대적인 품질이 서서히 떨어지는 경향을 보여줍니다. 실제 시스템에서는 요약 품질이나 중요 정보 손실 정도를 지표로 삼아 context rot를 측정할 수 있습니다.

## 결론 및 개선 방안

이번 실습을 통해 토큰 카운터, 롤링 컨텍스트 윈도우, 파일 기반 상태 저장 시스템을 통합하여 긴 루프를 관리할 수 있음을 확인했습니다. 다음과 같은 개선점을 제안합니다.

- 압축 요약을 생성할 때 중요한 함수 시그니처나 변수명을 별도의 리스트로 보존하면 재확인 시 도움이 됩니다.
- 토큰 사용량과 비용을 시각화하여 장시간 실행 시 비용 추이를 쉽게 파악할 수 있도록 합니다.
- 컨텍스트 초기화 로직을 추가하여 특정 조건(예: 오류 발생)에서 자동으로 새 세션을 시작할 수 있도록 만듭니다.

제안된 개선 사항을 반영하여 Ralph 루프의 안정성과 효율성을 더욱 향상시킬 수 있을 것입니다.
